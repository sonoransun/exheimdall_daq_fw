# docs/ — the HeIMDALL DAQ project site

This directory is a self-contained [GitHub Pages](https://pages.github.com/) site
built with plain Jekyll: no Gemfile, no plugins beyond the GitHub Pages defaults,
no npm, no build step. This README is excluded from the site.

| Path | What it is |
|---|---|
| `index.md`, `architecture.md`, `scaling.md`, `active.md`, `status.md`, `library.md`, `404.md` | The hand-written pages |
| `guide/` | Copies of `../Documentation/*.md`, generated by the sync tool. Do not edit them by hand |
| `_layouts/`, `_includes/` | Page layouts, inline SVG figures, badge and link helpers |
| `_data/packages.yml` | Work-package status that drives every status badge and note |
| `_data/pkg_states.yml` | The badge states, their order and their legend wording |
| `_data/guide.yml` | Library index, generated by the sync tool |
| `assets/css/site.css`, `assets/js/theme.js` | Hand-written styles; an optional theme toggle (the site works without JavaScript) |
| `_tools/` | `sync_docs.py` and `check_links.py` (not published: Jekyll skips `_` directories) |

## Enable GitHub Pages

1. Push the repository with this `docs/` directory on the default branch.
2. On GitHub, open **Settings → Pages**.
3. Under **Build and deployment**, choose **Source: Deploy from a branch**, then the
   branch (for example `main`) and the folder **`/docs`**. Save.
4. The site is published at <https://sonoransun.github.io/exheimdall_daq_fw/>.
   `_config.yml` sets `url: "https://sonoransun.github.io"` and
   `baseurl: "/exheimdall_daq_fw"` explicitly, so local builds produce the same links.
   For a fork, change both to your owner and repository name; for a custom domain
   or a user site, set `baseurl: ""`.
5. `repo_url` is set to `https://github.com/sonoransun/exheimdall_daq_fw`. The footer
   and guide links that point outside `Documentation/` (for example `../CHANGELOG.md`)
   become links into the repository; set it to `""` to render them as code text.
6. Re-run `python3 docs/_tools/sync_docs.py` as the last step before publishing, so
   the guide matches `Documentation/`.

## Re-sync the guide

Run this after any change under `Documentation/` (standard library only, Python 3.8+):

```bash
python3 docs/_tools/sync_docs.py           # rewrite docs/guide/ and docs/_data/guide.yml
python3 docs/_tools/sync_docs.py --check   # exit 1 if the copies are out of date (for CI)
```

Add the `--check` line to CI, so that a change to `Documentation/` without a re-sync
fails loudly.

The tool adds front matter (title from the first `#` heading), pins each heading to
its GitHub-style anchor, rewrites `foo.md#x` links to `foo.html#x`, turns links that
leave `Documentation/` into repository links, and renders
`<!-- verify-after: WP-xx -->` markers as visible status notes from `_data/packages.yml`.
A marker on its own line moves directly under its section heading; a marker inside a
sentence or a table cell stays inline. Guides that describe unreviewed work without
markers get a page-level note from `PAGE_VERIFY` at the top of the tool. To change how
the library groups documents, edit `GROUPS` there too.

To update package status, edit `_data/packages.yml`. `badge` is one of `done`,
`done · test defect`, `in review`, `in progress`, `planned` (listed in
`_data/pkg_states.yml`); `class` is `shipped` (for done), `risk`, `review`, `progress`
or `planned`. "Done" means implemented and reviewed in the working tree, not released.
Every badge, card summary and guide note on the site follows.

## Preview locally

With Ruby and Bundler, from this directory:

```bash
cat > /tmp/Gemfile <<'G'
source "https://rubygems.org"
gem "github-pages", group: :jekyll_plugins
G
BUNDLE_GEMFILE=/tmp/Gemfile bundle install
BUNDLE_GEMFILE=/tmp/Gemfile bundle exec jekyll serve --source . --destination /tmp/heimdall-site --baseurl /exheimdall_daq_fw
```

Or with any Jekyll 3.9 or 4.x in a container:

```bash
docker run --rm -p 4000:4000 -v "$PWD":/srv/jekyll -w /srv/jekyll jekyll/jekyll:4.2.2 \
  jekyll serve --host 0.0.0.0 --destination /tmp/_site
```

Then open <http://localhost:4000/>. After a build, check internal links and anchors:

```bash
python3 docs/_tools/check_links.py /tmp/heimdall-site --baseurl /exheimdall_daq_fw
```

With `--baseurl`, a site-relative link that lacks the prefix (one that skipped the
`relative_url` filter) counts as a problem.
